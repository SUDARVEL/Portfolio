## 1) Site map (simple architecture)

Keep navigation short. Every path should end at **Work** or **Contact**.

```
Home
 ├── Hero (who you are + bottom line)
 ├── Selected work (3 teaser cards → case studies)
 ├── About / craft (short personality + proof)
 └── Closing CTA → Contact

Work                 → list of 3 case studies
Work / [project]     → full case study (canvas below)
Gallery              → optional wow (3D) — never replace Work
Resume               → experience + skills
Contact              → form / email
```

**Rules from the book + research**
- Tease case studies on Home — don’t link project cards to company websites.
- Lead people to contact you.
- First impression in ~5–10 seconds: name, role, one promise, one CTA.
- Motion helps the story; it must never block reading.

## 3) Best storytelling model (one sentence)

**Show the ending first, then prove how you got there.**

Movie version of your case study:
1. **Poster** = title + final UI preview + impact line  
2. **Setup** = who / role / challenge  
3. **Conflict** = status quo (what was broken)  
4. **Journey** = just enough process (decisions, not every wireframe)  
5. **Climax** = final solution showcase  
6. **Payoff** = impact + learnings  

This matches the book (“bottom line up front”, “outcome first”) and fixes what most Wall-of-Portfolios sites miss (pretty visuals, thin problem→result story).
